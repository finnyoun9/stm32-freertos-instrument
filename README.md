# STM32 FreeRTOS 便携测量仪 · 学习与开发记录

跟着 **铁头山羊《FreeRTOS 教程（基于 HAL 库，自带示波器项目）》** 从零做一块开发板，把 FreeRTOS 从内核移植一路用到应用层，最后做出**成品：一台跑 FreeRTOS 的便携测量仪器**——**示波器 + 数字万用表 + 信号发生器**三合一，共用一套 ADC / DMA / LCD / 按键框架。

本仓库记录这整条链路：课程学习 → 开发板制作 → 内核移植 → 各机制实践 → 成品功能实现。

这个仓库的定位是**记录本**，不是代码发布仓库：

- 记录**过程**：开发板怎么来的、环境怎么搭、内核怎么移植、每章做了什么、踩了什么坑。
- 记录**掌握的东西**：每个 FreeRTOS 机制「我理解成什么 / 在哪个文件的哪一行用到了 / 拿什么证明它真的跑了」。
- 记录**证据**：照片、串口日志、示波器截图、代码片段、commit。

> 原则：**没验证过的不写"已完成"。** 空白格比编出来的结论值钱。

## 现在怎么用

1. 先看 [`docs/03-学习进度.md`](docs/03-学习进度.md)：51 条已按真实代码回填「我的实现」，**把 🟡 逐条变成 ✅**（补运行证据）。
2. 每学一个机制，在 [`docs/04-FreeRTOS-知识体系.md`](docs/04-FreeRTOS-知识体系.md) 对应条目里写「我的理解」（项目落点已经填好了）。
3. 凡是写了「已验证」的结论，必须在 [`docs/07-证据清单.md`](docs/07-证据清单.md) 里有对应条目。
4. 踩坑随手记进 [`docs/06-问题与排障日志.md`](docs/06-问题与排障日志.md)，别等想起来再补。
5. 回看视频时对着 [`docs/09-课程分集复习.md`](docs/09-课程分集复习.md) 走：它按集数给了概念线索 + 你代码里的落点。**注意它标注的 🔍 处需你回视频确认**（该文件不是视频转写）。
6. 复习任务划分 / IPC / 触发链时看 [`docs/diagrams/README.md`](docs/diagrams/README.md)：索引 + 证据锚点 + 交付凭据。
7. **最高优先级**：确认源码归属（[`firmware/README.md`](firmware/README.md) 的「待确认」）——这决定简历上能写什么。
