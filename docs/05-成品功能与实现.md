## 2. 整机数据流

```text
                      ┌──────────── 示波器 ────────────┐
PA1 ──► ADC1 常规序列 ──(TIM3 TRGO 128.1kSa/s)──► DMA1_Ch1 ──► rawDataBuffer[1024]
                                                                    │
PA3 ──► EXTI3 上升沿触发 ──► 启动 DMA 采集 ──► 完成中断 ──► 换算 waveform[1024]
                                                                    │ 事件组 bit
                                                                    ▼
                                                              ┌───────────┐
PA4 ◄── DAC1 ◄── DMA ◄── TIM5 ──► 信号发生器                   │  LCD 任务  │──► SPI1+DMA ──► 320×240 屏
           （正弦/三角/方波，≤500kHz 更新率）                    │（事件组等待）│
                                                              └───────────┘
PA0/PB1/PB0/VREFINT ──► ADC1 注入序列 ──(TIM2 TRGO 10Hz)──► 完成中断
                          │                                      │
                    触发电压/万用表/电源/VREFINT              邮箱（queue len 1）
                          └──────────────────────────────────────┘
```

## 3. FreeRTOS 任务划分（`Core/Src/main.c` L134-138）

| 任务 | 优先级 | 栈（word/B） | 触发/周期 | 阻塞在什么上 | 与谁通信 |
| --- | --- | --- | --- | --- | --- |
| `vKeyTask` | **3**（最高） | 128 / 512B | 10ms 轮询 | `vTaskDelay(10ms)` | 直接调 GUI 面板函数 + `Buzzer_Beep()` |
| `vBuzzerTask` | 1 | 128 / 512B | 被信号量唤醒 | **计数信号量** | 被 6 个按键 give |
| `vLCDTask` | 1 | 256 / 1KB | 被事件组唤醒 | **事件组**（9 个重绘位） | 读事件组位 → 重绘对应面板；SPI DMA 完成靠二进制信号量 |
| `vLEDTask` | 0（最低） | 128 / 512B | 100ms 翻转 | `vTaskDelay` | — |
| 定时器服务任务 | 4 | 128 / 512B | 内核自动创建 | 定时器命令队列 | Hold-Off / Force Trigger 两个软定时器 |

> 栈合计 2.5KB，`configTOTAL_HEAP_SIZE` 只有 **8KB**——这就是第 5 章「堆内存优化」要算的账。

**为什么这样切任务（我的理解，待补充确认）**：按键和蜂鸣器分开，是为了让「扫描」和「响」解耦；LCD 单独一个任务 + 事件组，是为了让**任何**事件源（按键、ADC 中断、软定时器）都能请求重绘，而不用互相等待。

## 4. 示波器

### 4.1 采样链路（代码事实）

| 环节 | 配置 | 数值 |
| --- | --- | --- |
| ADC | ADC1 常规序列，扫描模式，外部触发 `TIM3_TRGO` | 通道 `ADC_CHANNEL_1`（PA1），采样时间 1.5 周期 |
| 采样率 | TIM3：`72MHz/(PSC+1)/(ARR+1)`，当前 PSC=0、ARR=561 | **≈128.1 kSa/s** |
| 搬运 | DMA1_Channel1，循环搬运 1024 个 16 位 | 深度 **1024 点** |
| 换算 | `V = raw/4095×VDDA×2 − 2.5` | 对应 ÷2 分压 + 2.5V 偏置，量程约 ±2.5V |
| 采样率可调 | `WaveformCapture_SetSampleRate(PSC, ARR)` + `GetSampleRate()` 反算 | 支持运行时改时基 |

### 4.2 触发（这是最值得讲的部分）

| 机制 | 实现 | 依据 |
| --- | --- | --- |
| 外部触发 | PA3 EXTI3 上升沿中断 | `HAL_GPIO_EXTI_Callback` |
| 触发后动作 | **先关自己的中断**（防重入）→ `HAL_ADC_Start_DMA` 采 1024 点 → 启动 Hold-Off 定时器 → 复位强制触发定时器 | `waveform_capture.c` L80-95 |
| Hold-Off | **10ms 单次软定时器**：到期清 EXTI 标志并重新使能中断 | `HoldOffTimerCallback` |
| 强制触发 | **100ms 周期软定时器**：软件产生一次 EXTI3 事件 | `ForceTriggerTimerCallback` + `__HAL_GPIO_EXTI_GENERATE_SWIT` |
| 采集完成 | DMA 完成回调里换算 1024 点，然后 `xEventGroupSetBitsFromISR` 通知 LCD 任务 | `HAL_ADC_ConvCpltCallback` |
| 触发电压 | 由 DMM 注入序列 rank4 读回（电位器） | `App/dmm.c` L69 |

> 为什么用「软定时器」而不是 `vTaskDelay`：Hold-Off 必须**在中断上下文**里启动，而且它的作用是「一段时间内禁止再次触发」，用定时器表达最自然，也不用额外任务。
> 强制触发解决的是「信号太慢/没有边沿时屏幕一直不刷新」的问题——示波器里的自动触发（Auto）。

## 5. 数字万用表（`App/dmm.c`）

| 项 | 实现 |
| --- | --- |
| 采集 | ADC1 **注入序列** 4 通道，`TIM2_TRGO` 10Hz 触发（`72MHz/7200/1000`） |
| 通道分配 | rank1 = CH9(PB1) 万用表运放输出；rank2 = VREFINT；rank3 = CH8(PB0) 稳压电源；rank4 = CH0(PA0) 触发电压 |
| 参考源校准 | `VDDA = 4095 / VREFINT_raw × 1.205V`，**每次采样都用它换算**，不写死 3.3V |
| 挡位识别 | 读 6 个 GPIO（高电平有效）：2V/10V/50V、1k/10k/100k/1MΩ |
| 电压换算 | `Vin = Vadc×2 − 2`，再乘挡位系数 ×1 / ×5 / ×25 |
| 电阻换算 | `Rx = Vin/(2.5−Vin)×R0`，`R = R1·Rx/(R1−Rx)`，R1=2MΩ，R0=200/2k/20k/200k |
| 数据传递 | **邮箱**：`xQueueCreate(1, sizeof(DMMData_t))` + `xQueueOverwriteFromISR`（新值覆盖旧值）+ `xQueuePeek`（读而不取） |
| 停止位 | 待实测（万用表精度、与台式表对比误差） |

> 万用表刷新率 = TIM2 触发频率 = **10 Hz**。这里的设计取舍值得记：用邮箱而不是队列，是因为「万用表只需要最新的读数」，队列堆积旧值反而是负担。

## 6. 信号发生器（`App/waveform_generator.c`）

| 项 | 实现 |
| --- | --- |
| 硬件 | DAC_CH1（PA4）+ DMA + `TIM5_TRGO` |
| 更新率 | `72MHz/(71+1)/(1+1)` = **500 kHz** 上限；按输出频率自动取点（`sampleRate = 1000×f`，超 500k 时截断并重算点数） |
| 波形表 | 1000 点，12 位右对齐 |
| 波形 | 0=OFF（恒定 1241 ≈1V）、1=正弦（1±1V）、2=三角（1→2V）、3=方波（1V/2V） |
| 运行时切换 | `SetShape()` / `SetFrequency()` → 停 TIM+DAC → 重算表 → 重新 `HAL_DAC_Start_DMA` |

> ⚠️ 代码里三角波只做了**上升段**（`1.0 + i/N×1.0`），没有下降段——如果你在屏幕上看到的是锯齿而不是三角，根因就在这里。**这条要自己确认一下是不是有意的。**

## 7. 设计问题（要能自己讲出来）

1. 采样率的上限由 ADC 时钟 + 采样时间 + DMA 决定，想再快一倍要动哪里？（提示：12MHz ADC 时钟、1.5 周期采样 → 单次转换约 14 周期）
2. 示波器触发为什么要「先关中断再采集」？
3. 万用表为什么用邮箱而不是队列？用队列会怎样？
4. 信号发生器和示波器共用 DMA 控制器和 LCD，切换模式时会互相影响吗？
5. LCD 重绘为什么用事件组而不是队列？（多事件源、按位合并、可 `xClearOnExit`）
6. 8KB 堆够不够？开 `configCHECK_FOR_STACK_OVERFLOW` 和栈水位后会看到什么？
