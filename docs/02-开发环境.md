## FreeRTOS 移植要点

| 步骤 | 实际做法 | 依据 |
| --- | --- | --- |
| 内核来源 | FreeRTOS V11.1.0，随工程放在 `FreeRTOS/` | `FreeRTOS/Inc/task.h:56` |
| 端口选择 | GCC / ARM_CM3（Cortex-M3） | `FreeRTOS/Src/port.c` 文件头 |
| 堆方案 | **heap_4**（相邻空闲块合并，抗碎片） | `FreeRTOS/Src/heap_4.c` |
| 中断安装 | **向量表直连**：`startup_stm32f103rctx.s` 里 SVCall→`vPortSVCHandler`、PendSV→`xPortPendSVHandler`、SysTick→`xPortSysTickHandler`；`stm32f1xx_it.c` 里 CubeMX 生成的同名空函数是死代码 | `Core/Startup/startup_stm32f103rctx.s` L144/147/148 |
| 优先级分组 | HAL 用 `NVIC_PRIORITYGROUP_4`（4 位抢占优先级，与 `configPRIO_BITS=4` 匹配） | `stm32f1xx_hal.c:157` |
| HAL 时基 | 改用 TIM6 中断，把 SysTick 完整让给 FreeRTOS | `stm32f1xx_hal_timebase_tim.c`、`stm32f1xx_it.c` 的 `TIM6_IRQHandler` |
| 首次运行 | `xTaskCreate` 四个任务后 `vTaskStartScheduler()`，LCD 任务先点亮背光再进事件组等待 | `Core/Src/main.c` L128-138、`lcd_task.c` L44-58 |

### 中断安装的验证（有实测证据）

读回固件 ELF 的向量表，确认三个入口都指向 port.c 的函数（地址末位 `1` 是 Thumb 位）：

| 向量 | 地址 | 对应符号 |
| --- | --- | --- |
| SVCall | `0x080089e1` | `vPortSVCHandler`（`port.c` `0x080089e0`） |
| PendSV | `0x08008c61` | `xPortPendSVHandler`（`0x08008c60`） |
| SysTick | `0x08008ca9` | `xPortSysTickHandler`（`0x08008ca8`） |

> 证据目录：`docs/evidence/20260918-vector-table/`（脚本 `check_vector_table.py` + 原始输出）。
> 这一步对应课程 **2.4 安装中断服务程序**：装不对的表现就是「调度器不跑 / 一进临界区就 HardFault」。

## FreeRTOSConfig.h 关键配置（照抄实际值）

| 宏 | 实际值 | 说明 |
| --- | --- | --- |
| `configCPU_CLOCK_HZ` | 72000000 | 72MHz |
| `configTICK_RATE_HZ` | **100** | 1 个 tick = 10ms |
| `configMAX_PRIORITIES` | 5 | 优先级 0~4 |
| `configMINIMAL_STACK_SIZE` | 128 | 字（word）= 512 字节 |
| `configTOTAL_HEAP_SIZE` | **8192** | 8KB 堆（4 个任务的栈都从这里分配） |
| `configUSE_PREEMPTION` | 1 | 抢占式 |
| `configUSE_TIME_SLICING` | 1 | 同优先级轮转 |
| `configUSE_IDLE_SHOULD_YIELD` | 1 | 空闲任务主动让出 |
| `configUSE_TIMERS` | 1 | 软件定时器（优先级 = `MAX-1` = 4，队列长度 10） |
| `configUSE_COUNTING_SEMAPHORES` | 1 | 计数信号量（蜂鸣器用） |
| `configUSE_MUTEXES` / `RECURSIVE` | 1 / 1 | 已开启 |
| `configUSE_EVENT_GROUPS` | 1 | **LCD 重绘调度靠事件组** |
| `configUSE_STREAM_BUFFERS` | 0 | 未用 |
| `configUSE_TASK_NOTIFICATIONS` | 1 | 已开启 |
| `configMAX_SYSCALL_INTERRUPT_PRIORITY` | `5<<4` | 数值 ≥5 的中断里才能调 FreeRTOS API |
| `configKERNEL_INTERRUPT_PRIORITY` | `15<<4` | PendSV/SysTick 最低优先级 |
| `configSUPPORT_STATIC_ALLOCATION` | 0 / 动态 1 | 全部动态分配 |
| `configCHECK_FOR_STACK_OVERFLOW` | **0** | ⚠️ 未开，栈溢出查不出来（见 `docs/08`） |
| `configGENERATE_RUN_TIME_STATS` | 0 | 未开 CPU 占用统计 |
| `configUSE_TRACE_FACILITY` | 0 | 未开 `vTaskList` |
| `INCLUDE_uxTaskGetStackHighWaterMark` | **0** | ⚠️ 栈水位查不了（见 `docs/08`） |
| `configUSE_NEWLIB_REENTRANT` | 1 | newlib 可重入（`printf` 等） |

### 中断优先级实际分配（数值越小优先级越高）

| 中断 | NVIC 优先级 | 能不能调 FreeRTOS API |
| --- | --- | --- |
| DMA2_Channel3（DAC） | 0 | ❌ 高于阈值 5 |
| EXTI3（示波器触发） | 5 | ✅ 边界值，可以 |
| DMA1_Channel1（ADC） | 6 | ✅ |
| DMA1_Channel3（SPI1 TX） | 6 | ✅ |

> ⚠️ **待确认**：DAC 的 DMA 中断当前是 0，虽然 `HAL_DAC_Start_DMA` 的回调里没有调用 FreeRTOS API，但这是个隐患。要么把回调写干净，要么把优先级降到 ≥5。
